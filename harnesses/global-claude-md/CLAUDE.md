# Global preferences

Polyglot developer. Primary stacks: **TypeScript/web**, **Python**, and **systems (Rust/Go/C)**.
Main use cases: building features, reviewing & shipping PRs, and quick prototyping.

## How I like to work
- Match the conventions already in a file/repo over any general style preference.
- Be concise. Lead with the answer; keep explanation proportional to the size of the change.
- Verify before claiming done — run the build/tests/app when the change is testable, and say so honestly if you didn't or couldn't.
- Don't add code comments unless the "why" is non-obvious. No comments that just restate the code.
- For non-trivial or hard-to-reverse changes, outline the approach before doing it.

## Git & shipping
- Branch before committing if I'm on the default branch; commit/push only when I ask.
